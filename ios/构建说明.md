# iOS 真机安装与验证

本工程的 iOS 部分在 Linux 沙箱中**未经编译与真机验证**。Android APK 不能安装到 iPhone。

## 准备

- 一台 Mac、Xcode（含 iOS SDK）、Flutter stable / Dart 3、CocoaPods；本工程生成于 Flutter 3.50.0 / Dart 3.14.0。
- iPhone 用数据线连接 Mac，解锁并信任电脑；在系统提示时启用开发者模式。
- 在工程根目录运行 `flutter pub get`，随后 `flutter build ios --config-only --no-codesign`，再执行 `cd ios && pod install`。首次会下载构建依赖，安装后的游戏可离线运行。
- 当前 Flutter 工程包含 SDK 默认的 Swift Package Manager 配置，同时提供标准 Podfile；无第三方蓝牙插件。不要单独删除 Flutter 生成的 ephemeral 包目录；用上述 Flutter 命令重新生成即可。

## Xcode 安装

1. 打开 `ios/Runner.xcworkspace`，不要只打开 xcodeproj。
2. 选择 Runner → Signing & Capabilities，勾选 Automatically manage signing。
3. 在 Xcode Settings → Accounts 添加自己的免费 Apple ID，并选择对应 Personal Team；若包标识冲突，将 `cn.offline.doudizhu` 改为自己的唯一 Bundle Identifier。
4. 顶部运行目标选连接的真机，点击 Run。
5. 首次运行可能需要在 iPhone“设置 → 通用 → VPN 与设备管理”信任开发者；免费签名通常有效 7 天，到期需重新安装。
6. 首次联机允许“本地网络”访问，并开启蓝牙与 Wi-Fi。拒绝后可在 iPhone 设置中重新允许。单机不需要这些权限。

## 两台/三台真机验收

- 一台创建房间，其他 iPhone 搜索并加入；两人模式第三席为 AI。
- 测试 3 分叫地主、出牌/过牌、结算、再来一局。
- 客人关闭 App/蓝牙后，房主应显示掉线；机器人接管前可重新加入并恢复当前手牌。接管后原座位可能已释放。
- 房主断开时客人应收到提示，当前局结束，返回菜单重新建房。
- 背景/锁屏可能导致系统暂停连接；请在前台进行对局。

## 平台限制

iOS 使用 MultipeerConnectivity，不是 Android 的经典蓝牙 RFCOMM。系统自行选择蓝牙或点对点 Wi-Fi，应用无法强制纯蓝牙，因此不能声称 iOS 已实现“仅走真蓝牙”。无需互联网、服务器或同一路由器，但两端需要开启 Wi-Fi 与蓝牙。安卓和 iPhone 之间不能互连。本版本未加入可选的跨平台 Wi-Fi TCP 模式。

## 1.7.0 声音验收
音效通过 AVAudioPlayer 播放本地 WAV，默认开启；报牌用 AVSpeechSynthesizer，默认关闭。声音设置保存在 UserDefaults。请在真机检查声音开关、总静音、系统静音键与切后台停止播放；确认系统有中文语音后开启报牌。无中文 voice 时静默跳过，不要求下载，不影响出牌。Linux 环境未编译或试听 iOS。
